# WebP Delivery Derivatives

This directory is reserved for WebP files generated by
`.github/workflows/convert-images-to-webp.yml` and its CSV report.

## Master images remain untouched

The original PNG/JPEG files stay in the parent `images/` folder.
The workflow never overwrites, deletes, resizes, renames, or recompresses
those sources.

For each source, the workflow mirrors its relative path and appends
`.webp` to its full filename. For example:

- Source: `images/portrait.png`
- Derivative: `images/webp/portrait.png.webp`

Do not manually add master images or unrelated assets to this generated-only
directory.

## Conversion profiles

| Source | Profile | Fidelity |
|---|---|---|
| PNG | `-lossless -q 100 -m 6 -exact` | Pixel-exact lossless encoding, including RGB values in fully transparent pixels |
| JPEG | `-preset picture -q 92 -m 6 -sharp_yuv` | High-quality lossy encoding; not pixel-identical |

Both profiles request ICC profile copying with `-metadata icc`. EXIF and XMP
metadata are not copied. They remain in the untouched original file.

Animated PNG (APNG) is skipped rather than flattened. The skip is recorded in
the report because `cwebp` does not encode animated PNG input.

## Size comparison

See [conversion-report.csv](conversion-report.csv). It records source/output
paths, byte sizes, percentage size change, encoder version, profile, metadata
handling, and status. A negative size reduction means the WebP is larger than
its source. The workflow still keeps that WebP so the user can inspect it.

The report measures file size, not visual quality. The user makes the final
visual comparison before choosing which file to use for delivery.
